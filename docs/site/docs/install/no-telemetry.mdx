# No Telemetry

The Parthenon source installer makes **zero** telemetry connections. It has no analytics SDK, crash reporter, usage tracking, or opt-in failure reporting. The install path only contacts services required to fetch source code and pull runtime containers.

## What the installer connects to

| Destination | Why | When |
|---|---|---|
| `parthenon.acumenus.net` | Serve the public `install.sh` bootstrap | When you run the documented `curl` command |
| `api.github.com` | Resolve the latest release tag when no `--version` is provided | Once per install |
| `github.com/Acumenus-Data-Sciences/Parthenon` and `codeload.github.com` | Clone the repo or download the tagged source archive | Once per install |
| Docker Hub / GHCR (`docker.io`, `ghcr.io`) | Pull container images for Parthenon services | Once per install, and later only when you intentionally pull newer images |

That's it for the supported source installer. The native GUI/updater track is paused and is not the current public Community install path.

## What we don't do

- **No analytics SDK.** No Sentry, Mixpanel, PostHog, GA, Plausible, Amplitude, or similar.
- **No crash reporter.** If the installer crashes, you decide whether to file an issue.
- **No usage tracking.** We do not know how many people installed, cancelled, or opened Parthenon.
- **No phone-home for feature flags.** Feature toggles ship as source and configuration.
- **No opt-in failure reporting.** Users explicitly choose what to share when they file a GitHub issue or discussion.
- **No fingerprinting.** No MAC address, hostname, or installation ID is generated or transmitted for telemetry.

## How to verify

Don't take our word for it. Capture all outbound traffic without a destination whitelist, then confirm only the expected hosts appear. A whitelist filter would hide unexpected traffic and defeat the test.

### macOS

macOS does not provide tcpdump's Linux `-i any` interface. Capture on your active interface, or use `pktap` to capture multiple interfaces:

```bash
networksetup -listallhardwareports | grep -A 1 'Wi-Fi\|Ethernet'
sudo tcpdump -i pktap,en0 -nn -s 0 -A 'tcp port 443'
```

Run the installer while the capture is active. Expected TLS destinations are `parthenon.acumenus.net`, `api.github.com`, `github.com`, `codeload.github.com`, Docker registry hosts, and `ghcr.io`.

For a friendlier UI, use [Little Snitch](https://www.obdev.at/products/littlesnitch/) and set every connection to "ask" so each outbound destination appears as an interactive prompt.

### Linux

```bash
sudo tcpdump -i any -nn -s 0 -A 'tcp port 443 and not net 127.0.0.0/8'
```

Expected destinations are the same as macOS: Acumenus install hosting, GitHub source endpoints, Docker registry hosts, and GHCR.

### Windows

Run the installer inside WSL 2 and capture either from the WSL distro or with Wireshark on Windows:

```text
http.host or tls.handshake.extensions_server_name
```

Only Acumenus install hosting, GitHub source endpoints, Docker registry hosts, and GHCR should appear during the supported install.

## The feedback link is user-initiated

Public docs and the paused native GUI include passive GitHub links, such as:

```text
https://github.com/Acumenus-Data-Sciences/Parthenon/discussions
```

Clicking one opens GitHub in your browser. Nothing is sent automatically. You decide what to share, when, and through what channel.

## Why we chose zero telemetry

Two reasons:

1. **Healthcare context.** Parthenon is built for healthcare-IT teams. Buyers in that space face strict policies around third-party API calls and supply-chain visibility.
2. **Trust is finite.** Acumenus Data Sciences is a nonprofit. Adding a phone-home channel, even one we would never abuse, costs more trust than it returns in signal.

## What if we change this?

If a future version of the Parthenon installer adds telemetry, it will be:

1. **Opt-in only**, never opt-out
2. **Documented here before the change ships**
3. **Announced via a security advisory** so existing users can decide whether to opt in
4. **Cryptographically separable** so users can verify what is sent before each call

For now: zero. The relevant source is `frontend/public/install.sh`, `installer/install.sh`, and the Python installer path launched from the checked-out source tree.
