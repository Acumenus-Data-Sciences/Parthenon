# Source Installer Trust Checks

The current Parthenon Community install path is source-based. You run a public `install.sh` bootstrap, it downloads a tagged source tree, and the Python installer starts the local Community stack.

Older first-launch warnings for `.app`, `.msi`, `.deb`, `.rpm`, and `.AppImage` installers do not apply to the current public release because native packages are paused. This page replaces those binary-launch instructions with the trust checks that matter for the source installer.

## Before running the bootstrap

Download and inspect the script:

```bash
curl -fsSLo parthenon-install.sh https://parthenon.acumenus.net/install.sh
less parthenon-install.sh
```

Confirm it points at the Acumenus repository:

```bash
grep 'Acumenus-Data-Sciences/Parthenon' parthenon-install.sh
```

Compare the live script to the repository copy if your environment requires independent review:

```bash
curl -fsSLo repo-install.sh \
  https://raw.githubusercontent.com/Acumenus-Data-Sciences/Parthenon/main/frontend/public/install.sh
cmp parthenon-install.sh repo-install.sh
```

No output from `cmp` means the files match.

## Pin the source version

Use a tagged release for repeatable installs:

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh -s -- --version v1.0.9
```

Verify the tag before running it:

```bash
git ls-remote --tags https://github.com/Acumenus-Data-Sciences/Parthenon.git refs/tags/v1.0.9
```

Save the resolved commit SHA with your deployment record.

## macOS and Linux prompts

The source installer runs in a shell, so macOS Gatekeeper and Linux package managers do not show native app trust prompts. The meaningful prompts are shell-visible:

- `curl` fails if TLS or the HTTPS endpoint fails.
- `sh` runs only the script you pipe or download.
- Docker may ask for permission to start or may fail if the daemon is not running.
- The installer may prompt before changing local files or starting services.

If your policy forbids `curl | sh`, use the inspect-then-run form:

```bash
curl -fsSLo parthenon-install.sh https://parthenon.acumenus.net/install.sh
less parthenon-install.sh
sh parthenon-install.sh --version v1.0.9
```

## Windows prompts

Run the supported installer inside WSL 2. Windows SmartScreen does not apply to the source bootstrap because there is no Windows `.msi` in the current public release.

Docker Desktop may prompt for WSL integration or firewall access. Enable integration for the Ubuntu or Debian distro you use to run Parthenon, then re-run the installer check.

## If native packages return

When native packages resume, this page must be updated with current instructions for:

- macOS Gatekeeper, code signing, and notarization
- Windows SmartScreen and Authenticode or Trusted Signing
- Linux package signatures and checksums
- Tauri updater signatures

Until a release explicitly publishes those assets and verification steps, use the source installer verification flow above.
