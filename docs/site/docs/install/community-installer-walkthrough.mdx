# Community Source Installer Walkthrough

This is the current end-to-end walkthrough for a brand-new Parthenon Community install. Public Community releases are source-only: GitHub releases provide source code archives, and the supported install path runs the in-repo Python installer from that source tree.

Native `.dmg`, `.msi`, `.deb`, `.rpm`, `.AppImage`, and updater assets are paused until they are signed, reproducible, and covered by install smoke tests. Do not look for those artifacts in the current public release.

## Before you begin

Have ready:

- **Disk space:** at least 20 GB free at the install target
- **Memory:** at least 8 GB RAM for the Community stack
- **Network:** enough bandwidth for the source archive plus Docker image pulls
- **Docker:** Docker Desktop on macOS or Windows; Docker Engine with the Compose plugin on Linux
- **Time:** 15-25 minutes on a typical broadband connection

Windows installs run inside WSL 2. Open an Ubuntu or Debian WSL shell before running the bootstrap command.

## Linux or macOS

### 1. Start Docker

Start Docker Desktop on macOS or start Docker Engine on Linux:

```bash
docker --version
docker compose version
docker ps
```

`docker ps` should run without a daemon error before you continue.

### 2. Run the source bootstrap

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh
```

The bootstrap downloads the latest tagged source release into `~/Parthenon`, records the source reference in `.parthenon-source-ref`, and launches the browser installer.

Use a pinned tag when you need a repeatable deployment:

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh -s -- --version v1.0.7
```

Use a custom directory when you do not want to install under `~/Parthenon`:

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh -s -- --dir "$HOME/parthenon-community"
```

### 3. Configure

The installer opens the Configure step. Set the admin email, review the local URL, and leave advanced options collapsed for the default Community install.

### 4. Check

Preflight checks Docker, Docker Compose, Python, free disk space, and required ports. The most common blocker is a stopped Docker daemon; start Docker and run the check again.

### 5. Install

The installer runs the Community setup from the checked-out source tree. It pulls containers, starts Docker Compose, runs migrations, seeds roles and permissions, and prepares the local application.

If a phase fails, keep the install directory. Re-run:

```bash
cd ~/Parthenon
python3 install.py --webapp
```

The installer detects completed work and offers to resume.

### 6. Verify and sign in

When installation finishes, open:

```text
http://localhost:8082
```

Sign in with the admin credentials shown by the installer. On first sign-in, Parthenon requires a password change.

## Windows with WSL 2

### 1. Prepare WSL 2

From an Administrator PowerShell, install WSL 2 if needed:

```powershell
wsl --install -d Ubuntu-24.04
```

Reboot if Windows asks. Then open the Ubuntu shell and confirm Docker Desktop WSL integration is enabled for that distro.

### 2. Run the same bootstrap inside WSL

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh
```

The install runs inside Linux. Docker Desktop forwards `http://localhost:8082` to the Windows browser, so you can open Parthenon from either side once the stack is healthy.

## Headless or terminal-only install

Use `--cli` when no browser session is available:

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh -s -- --cli -- --community
```

For a pinned, terminal-only install:

```bash
curl -fsSL https://parthenon.acumenus.net/install.sh | sh -s -- --version v1.0.7 --cli -- --community
```

If you already have a source checkout, run the installer directly:

```bash
python3 install.py --webapp --community
```

For the full CLI surface:

```bash
python3 install.py --help
```

## What ready means

After completing the journey, you should see:

1. The Parthenon login screen at `http://localhost:8082`
2. A first-login setup or password-change flow for the admin account
3. The full Parthenon dashboard after password change

If any of these are not true, the install is not complete. Keep the source checkout and re-run the installer from that directory so it can resume with the existing state.

## Verification and trust

Before running the bootstrap in a regulated environment, verify the script and pinned source reference. See [Verifying the Source Installer](./verifying-signatures.mdx).

The installer does not send analytics, crash reports, or usage telemetry. See [No Telemetry](./no-telemetry.mdx) for the current network surface.

## What to do if anything fails

1. Check the [diagnostic knowledge base](https://github.com/Acumenus-Data-Sciences/Parthenon/blob/main/installer/diagnostics-kb.json) for your error pattern.
2. Open a [GitHub Discussion](https://github.com/Acumenus-Data-Sciences/Parthenon/discussions) with the install log.
3. For security-related issues, file a [security advisory](https://github.com/Acumenus-Data-Sciences/Parthenon/security/advisories) instead of a public issue.

Diagnostic-KB additions are welcome contributions. See [CONTRIBUTING.md](https://github.com/Acumenus-Data-Sciences/Parthenon/blob/main/CONTRIBUTING.md) for the process.
