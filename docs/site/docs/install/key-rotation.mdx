# Native GUI Updater Keypair

This page is a lineage note for the paused native GUI installer track. The current public Parthenon Community install path is source-only and does not consume a Tauri `latest.json` updater manifest.

Keep this document with the installer docs because it records the intended key-management procedure if signed native packages return. Do not use it as evidence that current Community releases publish native updater assets.

## When this procedure applies

Use this page only when all of the following are true:

1. Native GUI packages are being released again.
2. `installer/rust-gui/tauri.conf.json` contains a production updater public key.
3. CI publishes a signed Tauri updater manifest for the release.
4. Release smoke tests cover the native updater path.

Until those conditions are true, the active verification flow is [Verifying the Source Installer](./verifying-signatures.mdx).

## One-time generation

Run this on a trusted local machine. Do not generate release keys in CI or in a shared shell session.

```bash
mkdir -p ~/.tauri
tauri signer generate -w ~/.tauri/parthenon-updater.key
```

The command outputs:

- The private key at `~/.tauri/parthenon-updater.key`
- The public key on stdout

## Storage

| Material | Location | Purpose |
|---|---|---|
| Private key | GitHub repo secret `TAURI_UPDATER_PRIVATE_KEY` | CI signs the updater manifest |
| Private key passphrase | GitHub repo secret `TAURI_UPDATER_KEY_PASSWORD` | Unlocks the key in CI |
| Private key backup | 1Password vault `Parthenon - Release Keys` | Disaster recovery |
| Public key | `installer/rust-gui/tauri.conf.json` | Native GUI verifies updater signatures |
| Public key fingerprint | Acumenus security/release-keys page | Independent publication channel |

If the private key is not configured, CI must fail closed or publish no native updater manifest. A silent unsigned updater path is not acceptable.

## Replacing the placeholder

After generating the keypair:

1. Copy the printed public key.
2. Open `installer/rust-gui/tauri.conf.json`.
3. Replace the placeholder public key with the production key.
4. Add GitHub secrets `TAURI_UPDATER_PRIVATE_KEY` and `TAURI_UPDATER_KEY_PASSWORD`.
5. Tag a test release and verify that the native GUI rejects tampered updater metadata.

## Rotation

Rotate the keypair every five years, or immediately after suspected compromise.

Tauri 2 supports multiple public keys, so rotation can be staged:

1. Generate a new keypair on a trusted machine.
2. Add the new public key alongside the old key in `tauri.conf.json`, newest first.
3. Update CI secrets with the new private key and passphrase.
4. Publish a native test release and verify updater acceptance.
5. After one full supported update window, remove the old public key.

## After suspected compromise

1. Rotate to a new keypair immediately.
2. Issue a GitHub security advisory.
3. Bump the native installer's minimum supported version so older compromised update paths are rejected.
4. Publish the new public-key fingerprint through the independent Acumenus channel.

## User-facing verification

End users should not need to handle the updater key directly. If the native GUI track resumes, users who want independent verification can compare the bundled public-key fingerprint against the Acumenus security/release-keys page before running a native installer.

The fingerprint is reproducible from the public key:

```bash
printf '%s' '<pubkey-string>' | sha256sum
```
